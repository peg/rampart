Quickstart How it works

It reads. Rampart checks.

The agent can be talked into things. The rules can't.

Your agent believes what it reads

It opens a README to learn the project. Buried in it is a line written for the model. Small local models follow lines like that far more often than frontier ones do.

Rampart never reads the README

It has no model to persuade. It sees the tool call at the harness's hook, matches it against your rules, and answers before anything runs. Same input, same answer.

Four possible answers.

Every action the harness exposes gets exactly one, with the rule that gave it.

Allow

Ordinary work carries on. Builds, tests and edits inside the project run without a prompt.

ALLOW exec go test ./... [allow-unmatched]
Ask

Risky actions wait for you. Approve or deny from the terminal, the dashboard or the host's own approval card.

ASK exec kubectl apply -f production.yaml [guard-external-changes]
Deny

Prohibited actions are refused, including secrets that show up in a tool's response.

DENY read ~/.ssh/id_ed25519 [block-credential-access] DENY resp tool output contained a secret [block-credential-leaks]
Watch

Matches are recorded, nothing interrupts. Useful while you tune a new rule.

rampart audit tail --follow
Vendor safety layers stop at the vendor's product. Run a model through Ollama, LM Studio or llama.cpp and nothing stands between what it reads and what it runs.

Rampart is that layer for every other model. It is deterministic, runs on your machine, and needs no account and no second model. Hosted models get the same rules and the same audit trail.

Three commands to a guarded agent.

One binary for Linux, macOS and Windows. Nothing leaves your machine.

  1. Install

    From the Homebrew tap, the install script, or go install.

    brew install peg/tap/rampart

  2. Protect your agent

    Installs the hooks and managed policies, then verifies them.

    On a local model, rampart launch claude --model qwen3-coder refuses to start until protection is in place.

    rampart protect

  3. Watch it decide

    Every decision, live, with the rule that made it.

    rampart watch
    ALLOW exec go test ./... [allow-unmatched] DENY read ~/.ssh/id_ed25519 [block-credential-access] ASK exec kubectl apply … [guard-external-changes]

rampart protect installs hooks, managed policies and verification. rampart setup installs only the integration. Coverage differs by host, so check the support matrix before you rely on one.

Rules you can read in a minute.

YAML files on your disk. The standard set blocks credential reads, exfiltration and destructive commands out of the box.

Or skip the YAML

Quick rules from the command line, written to the same files.

rampart allow "npm install *"
Stop prompting for something you trust.
rampart block "curl * | bash"
Refuse a pattern everywhere.
rampart test "rm -rf /"
See which rule would answer, without running anything.
rampart pending --details
List actions waiting for you, then approve or deny them by id.
rampart audit verify
Check the hash chain of the local audit trail.

What it covers, and what it doesn't.

Read the threat model before you decide where to rely on Rampart.

Covered

  • Actions the harness exposesShell commands, file reads and writes, web fetches and MCP calls, at the hook, plugin or proxy the host provides.
  • A record you can checkEvery decision lands in a hash-chained local audit trail.
  • Approvals that wait for a personAsk decisions pause the action until someone answers.

Not covered

  • The inside of an allowed programRampart does not see arbitrary syscalls or network traffic in a process you already allowed. It is not a sandbox.
  • An agent running as youWhen the agent shares your OS user, treat approvals as a strong default, not a wall. Keep credentials and network access tight.
  • Hosts without a hookOther agents get a cooperative wrapper, which is explicitly limited.
