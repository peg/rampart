The problem

It reads. It believes.

Your agent opens a README to learn the project. Buried in it is a line written for the model, not for you. Small local models follow lines like that far more often than frontier ones.

The check

Rampart doesn't read. It checks.

Rampart never sees the README and has no model to persuade. It sees the tool call, matches it against your rules, and answers before anything runs.

Why local

Your model has no guard.

Vendor safety layers stop at the vendor's product. Run a model through Ollama, LM Studio or llama.cpp and nothing stands between what it reads and what it runs.

Rampart is that layer for every other model. Deterministic rules, so there is nothing to talk into a bad idea.

Get started

Three commands to a guarded agent.

  1. Install

    One binary. No account, nothing leaves your machine.

    brew install peg/tap/rampart
    Linux, macOS & Windows installation

  2. Launch

    Starts the agent on your local model, and refuses to start if protection is not in place.

    rampart launch claude --model qwen3-coder
    Local model guide

  3. Watch

    See decisions live, with the rule that made each one.

    rampart watch
    Follow the quickstart

Already running a hosted agent? rampart protect finds the agents you have installed and guards them in place.

Works with

Your harness. Your model.

Rampart guards the agent, not the model server, so it works with whatever your agent can talk to.

Ollama · native hooks

Claude Code

Run Claude Code on a local model with Rampart's hooks installed and verified first.

rampart launch claude --model qwen3-coder Claude Code setup and limits

Ollama or --oss · native hooks

Codex

The same one-command start for Codex, through Ollama or Codex's own open-model mode.

rampart launch codex --model gpt-oss:20b Codex setup and limits

Any provider · experimental plugin

OpenCode

A dependency-free plugin checks OpenCode's shell, file and patch tools before they run.

rampart setup opencode OpenCode setup and limits

Any provider · native plugin

OpenClaw

The bundled plugin connects to Rampart's local policy service, with approval cards in the app.

rampart protect openclaw OpenClaw setup and limits

Know the boundary

Honest about what it covers.

  • Rules you can read

    Policies are plain YAML on your disk. The standard set blocks credential reads, exfiltration and destructive commands out of the box.

    Explore the policy schema

  • A record you can check

    Decisions land in a hash-chained local audit trail, so you can see what your agent tried and what stopped it.

    Understand audit guarantees

  • Not a sandbox

    Rampart decides on the actions your harness exposes. It does not see inside a program you allowed. Pair it with sensible credentials and network limits.

    Read the threat model
