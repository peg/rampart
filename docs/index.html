Your agent reads, and believes.

It opens a README to learn the project. Buried in it is a line written for the model. Small local models follow lines like that far more often than frontier ones do.

Rampart doesn't read. It checks.

Rampart never sees the README and has no model to persuade. It sees the tool call at the harness's hook, matches it against your rules, and answers before anything runs. Same input, same answer, every time.

Allow

Ordinary work carries on. Builds, tests and edits inside the project run without a prompt.

ALLOW exec go test ./... [allow-unmatched]
Ask

Risky actions wait for you. Approve or deny from the terminal, the dashboard or the host's own approval card.

ASK exec kubectl apply -f production.yaml [guard-external-changes]
Deny

Prohibited actions are refused, including secrets that show up in a tool's response.

DENY read ~/.ssh/id_ed25519 [block-credential-access] DENY resp tool output contained a secret [block-credential-leaks]
Watch

Matches are recorded, nothing interrupts. Useful while you tune a new rule.

rampart audit tail --follow
Vendor safety layers stop at the vendor's product. Run a model through Ollama, LM Studio or llama.cpp and nothing stands between what it reads and what it runs.

Rampart is that layer for every other model. It is deterministic, it runs on your machine, and it needs no account and no second model. Hosted models benefit too: the same rules and the same audit trail apply whatever your agent talks to.

Three commands to a guarded agent.

One binary for Linux, macOS and Windows. Nothing leaves your machine.

  1. Install

    From the Homebrew tap, the install script, or go install.

    brew install peg/tap/rampart

  2. Protect your agent

    Installs the hooks and managed policies, then verifies them. Or launch an agent on a local model, which refuses to start until protection is in place.

    rampart protect

    On a local model: rampart launch claude --model qwen3-coder

  3. Watch it decide

    Every decision, live, with the rule that made it.

    rampart watch
    ALLOW exec go test ./... [allow-unmatched] DENY read ~/.ssh/id_ed25519 [block-credential-access] ASK exec kubectl apply -f prod… [guard-external-changes]

rampart protect installs hooks, managed policies and verification. rampart setup installs only the integration. Coverage and verifier strength differ by host, so check the support matrix before you rely on one.

Rules you can read in a minute.

Policies are YAML files on your disk. The standard set blocks credential reads, exfiltration and destructive commands out of the box. Add your own beside it.

Or skip the YAML

Quick rules from the command line, written to the same files.

rampart allow "npm install *"
Stop prompting for something you trust.
rampart block "curl * | bash"
Refuse a pattern everywhere.
rampart test "rm -rf /"
See which rule would answer, without running anything.
rampart pending --details
List actions waiting for approval, then rampart approve <id> or rampart deny <id>.
rampart audit verify
Check the hash chain of the local audit trail.

What it covers, and what it doesn't.

Start with the threat model when you decide where to rely on Rampart.

Actions the harness exposes

Shell commands, file reads and writes, web fetches and MCP calls, checked at the hook, plugin or proxy the host provides. Decisions go to a hash-chained local audit trail.

The audit trail

Approvals stay with a person

Ask decisions wait for a human. When the agent runs as your own OS user, treat approvals as a strong default rather than a hard wall, and keep credentials and network access sensible.

Policy reference

It is not a sandbox

Rampart does not see arbitrary syscalls or network traffic inside a program you already allowed. Pair it with a sandbox or container when you need isolation.
